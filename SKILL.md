# eidolon-setup

Read existing project settings and relevant stored preferences first. Reuse answers already given; do not ask the same opening questions whenever real work starts.

For requested onboarding, resolve only missing preferences about memory, verification, working style, and scope. Use [references/interview.md](references/interview.md) only for a requested deeper interview.

Load the relevant component: [references/remember.md](references/remember.md) for durable memory, [references/verify.md](references/verify.md) for evidence, or [references/collaborate.md](references/collaborate.md) for coaching. Preserve source integrity and user-only persona changes.

Record observed outcomes and scope, and verify the resulting setup. Proceed with already-authorized reversible work; ask for a new installation, identity change, sensitive/destructive operation, or external effect when it is not already authorized. An ordinary build/fix request does not automatically opt into onboarding.
